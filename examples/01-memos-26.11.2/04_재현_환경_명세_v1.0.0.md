## 3. 초기 합성 테스트 데이터 및 외부 서비스 테스트 대역 규약

### 3.1 합성 데이터 시드 (비밀키·개인정보 미포함)
- **호스트 계정**: `username=specadmin` (실측 수집) / `parityadmin` (대조 테스트 독립 실행), 합성 비밀번호 및 `.local` 이메일만 사용.
- **합성 메모 4종**:
  1. `M1` (`PUBLIC`): Markdown 제목 + `#release` `#architecture` 태그, 생성 시 `pinned: true` 전달(무시 확인) 후 `PATCH`로 고정 및 체크리스트(`- [x]`) 추가.
  2. `M2` (`PRIVATE`): 리터럴 와일드카드 경계 문자열 `50%_off` + `#security` `#audit` 태그, 공유 토큰 발급 대상.
  3. `M3` (`PUBLIC`): `NORMAL` → `ARCHIVED` 상태 전이 검증 대상(`#archive-test`).
  4. `M4` (`PRIVATE`): 영구 삭제(`DELETE`) 후 `404` 경계 검증 대상(`#ephemeral`).

### 3.2 외부 서비스·비결정적 요소 테스트 대역 정책 (`F-012`)
- **제외된 실외부 연동**: OAuth2 IdP, S3 버킷, SMTP 서버, 외부 AI API, MySQL/PostgreSQL 서버는 오프라인 격리 검증 범위에서 제외했습니다(`EV-013`, `Q-005`, `Q-006`).
- **재검증 방법**: 추후 확장 검증 시 로컬 OAuth2 목 서버(예: `oidc-provider`), MinIO(S3 호환), Mailpit(SMTP 목), Docker MySQL/PostgreSQL 컨테이너로 고정 테스트 대역을 구성해 동일 `07` 하네스에 연결합니다.
- **비결정적 필드 정규화**: `createTime`, `updateTime`, 생성된 `uid`·`share_token`, JWT 문자열 값 자체는 동등성 비교에서 제외하고 구조·상태 코드·개수·부울 속성·가시성·태그 집합으로 결정론적 비교를 수행합니다.
